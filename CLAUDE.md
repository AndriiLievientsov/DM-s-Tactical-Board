# CLAUDE.md — DM's Tactical Board

Контекст для новых сессий Claude Code. Коротко и по делу.

## 1. Что это
Виртуальный игровой стол (VTT) для D&D 5e в **одном HTML-файле**, без сервера и зависимостей. Мастер ведёт игру вживую, карта выводится на проектор/ТВ через отдельное «окно игроков». Работает offline, открывается двойным кликом (`file://`).

## 2. Устройство
| Файл | Что внутри |
|---|---|
| `index.html` | Всё приложение (~4000 строк): CSS → разметка → один `<script>`. Vanilla JS + Canvas 2D. |
| `tests/smoke.js` | Smoke-тест на Playwright (headless Chromium): ключевые сценарии + проверка, что в консоли нет ошибок. |
| `.github/workflows/ci.yml` | Job `test` (smoke) на каждом PR и push в `master`; job `automerge` — squash-мёрдж PR из `claude/*` (не draft) после зелёного теста. |
| `README.md` | Пользовательское описание всех функций, горячие клавиши, формат `.json`. |
| `pw.png` | Превью для README. |

Скрипт в `index.html` разбит на секции-баннеры `// ===== NAME =====` (ищи по `^//  [A-Z]`): HELPERS, STATE, DAMAGE, UNDO/REDO, AMBIENCE, ADVENTURE DATA (`normalizeAdventure`), AUTOSAVE, CANVAS RENDERER (сетка/гексы, стены/свет, туман, токены), MOVEMENT, MOUSE/EVENT HANDLERS (pointer events), TOOLBAR, SIDEBAR, LAYERS, ENCOUNTERS, TOKEN CONTEXT MENU, INITIATIVE, PINGS, SELECTION, HELP, DICE, TOKEN PROPERTIES, STAT BLOCK, AoE, PLAYER WINDOW, INIT.

Ключевые идеи:
- **Состояние**: глобальный `state`; данные приключения — `state.adventureData` (`locations[]`, `library[]`, `encounters`, `notes`, `version`). У локации: `tokens`, `drawings`, `fog`, `walls`, `lighting`, `vision`, `gridType`, `cellSize`, вид (zoom/offset), звук.
- **Мини-шина событий** `on/emit`; перерисовка — `drawCanvas()` (async, рисует всё заново).
- **Любая мутация** → `pushHistory()` (undo на 50 шагов, на одну локацию; картинки в снапшотах заменены ссылками `@@src:N`) → `markDirty()` → автосохранение в IndexedDB через ~2 с.
- **Импорт/восстановление** только через `applyAdventure()` → `normalizeAdventure()`. Новое поле данных = добавить нормализацию туда.
- **Окно игроков**: `index.html?player=1` (`isPlayer`), данные идут через `BroadcastChannel('dms_tactical_board')`, картинки отправляются один раз. Мастер-only данные (HP, скрытые токены/туман, стены, карточки) игрокам не передаются.
- **Свет**: `visibilityPolygon()` (raycast к концам стен + кольцо лучей; все углы в диапазоне −π…π!), `drawLighting()` — темнота, свет токенов, тёмное зрение PC, маска обзора персонажей.
- Имена в `innerHTML` — только через `esc()`.

## 3. Запуск и зависимости
- Приложение: открыть `index.html` в браузере. Зависимостей нет.
- Тест (нужен Node 18+):
  ```bash
  npm i --no-save playwright && npx playwright install chromium
  node tests/smoke.js
  ```
  В облачной сессии Claude Code браузер уже есть: `ln -sfn /opt/node-tools/node_modules node_modules && CHROMIUM_PATH=/opt/pw-browsers/chromium node tests/smoke.js; rm node_modules`. `node_modules` не коммитить.

## 4. Что сделано (всё в `master`, PR #2–#17)
Карта/зум/пан, квадратная и **гекс-сетка**, размер клетки на локацию, линейка (фт/клетки/гексы), туман (кисть/полигон/прямоугольник), рисование и ластик, токены (HP-бар, размер, поворот, статусы **с длительностью в раундах**, «мёртв», слои существа/объекты с замком, скрытые от игроков, дублирование с нумерацией, контекстное меню), карточка монстра (КД, скорость, атаки с бросками и критом), урон/лечение группе, дистанция движения за ход, трекер инициативы (бросить всем, следующий ход пропускает мёртвых), готовые встречи, AoE-шаблоны, кубики (формулы, показ игрокам), пинги, **стены/двери/динамический свет**, **тёмное зрение и обзор персонажей**, окно игроков, звук локации (Web Audio + свой файл), заметки, библиотека, автосохранение IndexedDB + восстановление, импорт/экспорт `.json` с валидацией, тач-управление (pinch, долгое касание = пинг), справка `?`, XSS-экранирование. Полный список — `README.md`.

## 5. Принятые решения и почему
- **Один файл `index.html`** — главная ценность проекта (флешка, мессенджер, offline). Не дробить без сборки, которая снова выдаёт один файл.
- **Без внешних библиотек/CDN** — работа без интернета на сессии.
- **IndexedDB вместо localStorage** — base64-карты не влезали в ~5 МБ, ошибки были тихими. Прошлая сессия копируется в слот `recovery`, чтобы новая её не затёрла; открытие страницы само по себе не сохраняет.
- **Окно игроков через BroadcastChannel** — без сервера; проверено, что работает и с `file://`.
- **Pointer Events** — одна логика для мыши, пера и тача.
- **Импорт: сначала валидация, потом замена** — битый файл не должен стирать сессию.
- **Undo сбрасывается при смене локации** — раньше undo подменял токены чужой локации.
- **Тёмное зрение/обзор работают только для токенов «Персонаж игрока»** — иначе монстры с тёмным зрением «подсвечивали» карту игрокам.
- **Автомёрдж без ревью** — явно одобрен владельцем: PR из `claude/*` мёрджатся сами после зелёного smoke-теста. Значит, smoke-тест — единственный барьер: **расширять его для каждой фичи, никогда не ослаблять/не отключать**.
- В репозитории параллельно работала вторая сессия (ветка `claude/project-thread-uhq1vx`). Договорённость: **перед каждым пушем мёрджить `origin/master`** в свою ветку.

## 6. Что осталось / баги / идеи
Технический долг:
- `index.html` > 4000 строк — растут конфликты. Вариант: модули в `src/` + скрипт сборки в один `index.html`.
- `drawCanvas()` перерисовывает всё и пересчитывает свет на каждое движение мыши → тормоза на больших картах. Нужен dirty-флаг + `requestAnimationFrame` + кэш полигонов видимости.
- Картинки дублируются base64 в каждом токене `.json` → пул картинок по хэшу.
- Нет юнит-тестов (кубики, гексы, видимость, `normalizeAdventure`, миграции старых файлов).
- Защита ветки `master` с обязательной проверкой `test` не включена (настраивает владелец в GitHub).
- Нет файла `LICENSE` (условия только текстом в README).

Известные ограничения: окно игроков — только на этом же компьютере; освещение общее для всех игроков; линейка — без промежуточных точек.

Идеи (по приоритету): импорт монстров SRD 5e; листы персонажей и проверки; подсказка спасброска концентрации при уроне; автооткрытие исследованного тумана; путь с waypoints и подсветка досягаемых клеток; журнал сессии; мультиплеер по WebRTC; шаблоны карт/токенов; таймер хода; локализация RU/EN.

## 7. Как со мной работать
- **Отвечать по-русски.** Код, комментарии в коде и сообщения коммитов — по-английски; заголовки и описания PR — по-русски.
- Коротко, по делу, без воды. Итог — что сделано, что проверено, что нет.
- Есть свобода действовать самостоятельно: делать, а не спрашивать по мелочам; спрашивать только при реальной развилке.
- Крупную работу — **поэтапно, по PR на этап**; PR открывать **не draft**, чтобы сработал автомёрдж.
- Перед пушем: `node tests/smoke.js` зелёный, новая фича покрыта тестом, визуальные изменения проверены скриншотом.
- Скриншоты и временные файлы — только вне репозитория (однажды они случайно попали в коммит). Никогда `git add -A` без проверки `git status`.
- Без force-push и переписывания истории; ветку синхронизировать merge-ом `origin/master`.
- После правок обновлять `README.md` (раздел функций, горячие клавиши, roadmap) и этот файл.
